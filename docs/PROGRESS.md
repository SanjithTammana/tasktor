## Interpretations
- **Linux build set.** CI's Linux job builds `Tasktor.Linux.slnf`, a solution filter without `Tasktor.Flyout` and `Tasktor.Widget` (WinUI / Windows App SDK do not build on Linux). The Windows job builds `Tasktor.sln`.
- **`net10.0-windows` projects run on Linux.** `Tasktor.Windows`, `Tasktor.Agent`, `Tasktor.Capture` and `Tasktor.Shell` target `net10.0-windows` (compiled on Linux with `EnableWindowsTargeting`); their test projects target the same TFM and run on Linux. Only code paths that call Win32 need Windows; everything else is tested here.
- **G-net from M0.** The banned-API analyzer (planned for M12/M15) is on from the start for every `src/` project; it costs nothing and stops accidents early. Network use lives only in plugins (outside `src/`).
- **No Flyout / Widget test projects yet.** Their testable logic lives in `Tasktor.Hosts.Common` (renderers, fitter), which has its own test project.
- **Schema ids.** `$id` is `urn:tasktor:schema:<file>` so the repo names no web domain it does not own; files point `$schema` at the shipped schema file (relative path) for editor autocomplete.
- **One schema file per root record.** `tasktor.action/1` is two files (`action-request-1`, `action-result-1`); `tasktor.plugin/1` is four (`plugin-1` manifest, `plugin-input-1`, `plugin-output-1`, `pack-1`). The contract id stays the same; the file name says which record.
- **Conditions and rule actions are flat records.** The rules grammar picks a condition / action kind by which key is present (`metric`, `learned`, `all`, …), not by a discriminator, so `Condition` and `RuleAction` are records with all keys optional; `RulesLoader` (M4) enforces exactly one kind per object. Value-states use `{"state": "fullscreen", "is": "exclusive"}`.
- **Action origins.** `widget`, `flyout`, `tray`, `toast`, `cli`, `rule`, plus `shell` for `tasktor-shell` (U3). Plugin card buttons arrive with the viewer's origin and the `plugin.action` action, which only reaches the plugin's own declared actions.
- **Args and targets are string maps** (`{"mode": "polite"}`, `{"pid": "4242"}`) so every origin (CLI included) sends the same shape.
- **Grouping rules live in `rules.json`.** A2.2 says grouping rules are `rules.json` entries, so `tasktor.rules/1` gained an additive `grouping` list (`match {exe|path|package} → group_as | attach: parent | never`).
- **The seven interfaces live in Contracts** (D-A5 §4) with their value types, so plugins' SDK and viewers share them; `IBlockRenderer` stays in the viewer hosts.
- **Own log sink instead of `Microsoft.Extensions.Logging`.** H6 asks for an AOT-safe logger without personal data; a 150-line `LogSink` with typed `LogField`s (primitives or `Sensitive<T>` only) keeps the agent dependency-free and makes redaction structural.
- **`AppGrouper` system bucket:** a process with no readable path that is not the user's own, plus PIDs 0 and 4, goes to "System / services" (A2.1 step 6).
- **Snapshot publishing is change-driven, not ticked.** D-H3 says ≤ 1/s on change; D-A3 says an idle agent wakes about once a minute. A 1 s timer would wake the agent 60 times a minute, so state updates call `MarkChanged`, which schedules a single publish at max(now, last + 1 s).
- **A toast click is the confirmation.** D-H4 lets a toast run destructive actions "only the toast itself offered" (e.g. `run`, A6's Close). A toast cannot show a second step, so for origin `toast` the offer (registered in `ToastOffers` when shown, withdrawn when the toast goes) replaces the confirm token.
- **The critical denylist blocks every mutating action**, not only End: priority, EcoQoS, caps, close and freeze on `csrss`, `lsass`, `dwm`, `explorer`, `tasktor-core` … are refused; read-only actions (open file location) pass. A3 only promises "End disabled"; changing a critical process's priority is no safer.
- **`preset.apply` is reversible-class but user-only**: U3 lets click / hotkey / `tasktor preset apply` move and launch without a confirm, while rules may only `arrange`. `UserOnly` encodes "never from a rule" (also used for `run` and `plugin.enable`).
- **Rule actions map onto catalog actions**: `pause: refits|tracking|capture` → `<x>.pause`; `pause: job:<id>|group:<g>` → `job.pause` (+ `mode`); `set_priority` → `priority.set`; `efficiency` → `efficiency.set`; `cap_cores` → `cores.cap`; `plugin_action: "<plugin>:<action>"` → `plugin.action`; `arrange` → `preset.arrange`; `capture_pause` / `capture_exclude` → `capture.pause` / `capture.exclude`; `use_fallback` / `relearn` → `learned.*`. Undo uses each row's catalog `Undo` partner; capture rows have none, so a rule never lifts a block.
- **Toast button vocabulary:** `open:<card>`, `run:<command>`, `snooze:<duration>`, or any catalog action offered on the toast surface (e.g. `job.log`, `rule.its_fine`, `disk.storage_settings`).
- **`pause: content`** pauses the content worker through `refits.pause` with target `{worker: content}` (I3, I13 mention pausing "the content worker" next to refits).
- **Pipe origins are bound to the client.** Any process of the user can open the pipe, so a client may only act with the origin its hello name maps to (`flyout` → flyout + toast, `widget`, `shell`); every other client acts as the CLI, so the CLI's `--yes` + `cli.allow_destructive` rule cannot be bypassed by claiming `flyout`. `PipeServer.OriginsFor` is the hook where Windows verifies the client's image path (see Windows checks).
- **Current-user pipe ACL via `PipeOptions.CurrentUserOnly`**, which sets a current-user-only DACL on Windows and owner-only permissions on Unix sockets, on both server and client.
- **CLI `--yes` travels as `confirm: "--yes"`** on the action request; the router accepts it only for origin `cli`.
- **`tasktor forget capture --since …`** maps to the catalog's `capture.forget`; other `forget` verbs to `forget` with target `{what}`.
- **`forget all` keeps** settings, rules, consents, the install key, notes, presets, plugins and plugin data, `pause.json` and `frozen.json` (frozen-job recovery must survive a forget). `forget tracking` also removes `state\projects.json` (I6's map is keyed by workflow ids that tracking produced).
- **`actions_log` / `alerts_log` exports come from the log files** (U2: "from H6; names only"), parsed back by `LogScanner`.
- **Golden files** (`tests/fixtures/export-sample`) are regenerated with `TASKTOR_REGEN_FIXTURES=1 dotnet test`; normal runs only compare.
- **Surface tags are enforced, not only displayed.** An action from the CLI, widget, tray or a toast must list that surface in its catalog row; the flyout and the shell reach every row. This keeps `plugin.enable` (whose consent dialog is in the flyout) and other flyout-only actions away from scripts.
- **A plugin's `id` must equal its folder name**, so a folder cannot impersonate another plugin's consent.
- **Plugin settings** live in `plugin-data\<id>\settings.json`; `secret` settings (e.g. an ICS URL, D-S5) are stored protected with the install key's `KeyProtection` (DPAPI on Windows) and passed to the plugin only on stdin.
- **A5's low-space alert is a built-in watch, not a grammar rule.** "Again only after 5 GB more are lost or 24 h" cannot be said in grammar v1, so `DiskGuard` implements it; `{ "id": "disk-low", "enabled": false }` in `rules.json` turns it off (the loader accepts a bare disabled entry, as D-H6 promises).
- **A6 re-arm hysteresis** ("falls 10 points below for 2 min") is approximated by the rules' 30 min cooldown plus the hold; the alert text and offender come from `Pressure` through rule-input fields (`{offender}`, `{growth}`, `{faster}`) and a global target (the offender app for the toast's Close button).
- **Network rates come from PDH** (`\Network Interface(*)\Bytes Received/sec`) in the same query as CPU / RAM / GPU / disk instead of `GetIfTable2` (D-A5: one API family = one class); the cumulative-counter path stays for other sources.
- **Card row actions** use the target value `{row}`, which the renderer replaces with the row's `row_key` value (per-row Close / Lower / End on `core.apps`, Kill on `module.ports`).
- **Pack rule ticks** are stored as consents named `pack:<pack>:<rule>`.
- **Package pins.** xUnit 2.9.3, Test SDK 17.14.1, BannedApiAnalyzers 4.14.0, Windows App SDK 2.5.1 (the version the U4 sources cite).

- **B's job gate uses tree CPU** (root + descendants), so a launcher whose work happens in a child still becomes a job; workers fold under the root.
- **Command lines** are read with `NtQueryInformationProcess(ProcessCommandLineInformation = 60)` (no WMI, which would need COM and is slow); they stay `Sensitive<string>` and are used only for the classifier and the hashed kind key.
- **"Efficiency mode" is EcoQoS only** (`SetProcessInformation(ProcessPowerThrottling)`), with no priority change; Task Manager's leaf icon also lowers the priority, which we leave to the separate Lower-priority action.
- **Polite pause is offered for any job with a live progress file**, not only "helper jobs": the helper (or any writer honouring `control.json`) is the thing that pauses, so the file is the capability.
- **Without `ProcessExitEvents` (non-Windows runs)** a job's end is noticed by the next scan; the exit code is then unknown. No extra portable source was added.
- **The freeze-recovery loop lives in `FrozenRegistry.Recover`** (portable, tested on Linux); `Win32ProcessControl.RecoverFrozen` passes its `Thaw`. A thaw that throws keeps the record for the next start; one that returns drops it even if a process had already exited.

- **ICS parsing is in-repo (OQ-S2 fallback)**, for both the agent (C#) and the calendar plugin (stdlib Python); a shared fixture keeps them identical. A `TZID` resolves to the system zone with that id, else to the file's own `VTIMEZONE`, else local: the agent runs with invariant globalization, so IANA ids cannot be mapped to Windows ids on Windows.
- **Calendar titles in the snapshot.** `state.calendar` (signed in the snapshot contract) carries the next event and the rest of today, so `snapshot.json` (the live view, overwritten) holds up to 8 titles. They are never logged and never written to any store; everything else about events stays in memory.
- **A deadlines-file line without a time** is due at 23:59 local that day.
- **Urgency for E2:** warn within 15 min, critical within 5; the 1-minute mark is the Join toast (`meeting.soon`).
- **One shared calendar table** (`CalendarFeed`) is held while any of E1 / E2 / I13 / I3 is on; Event mode's plumbing is always on (E11 needs it) but its calendar windows need the `event_mode` Module.
- **Bare rule toggles both ways.** `{ "id": "x", "enabled": true }` turns a shipped-off rule on (Settings' toggles write this), mirroring the signed `enabled: false`; the shipped rule keeps its origin and `builtin` flag.
- **Guard opt-in groups** are `meeting_guarded` and `battery_guarded` in the rules file (empty by default); the app-affecting guard rules target only them.
- **I3 microphone matching:** NonPackaged keys (`C:#…#Zoom.exe`) match by exe glob; packaged keys (`MSTeams_8wekyb3d8bbwe`) match a call-app exe by letters and digits. A browser counts only while `meeting_now`.
- **I3's notice and I13's countdown live on `core.guards`** (U4 lists no separate card for them).
- **`cap_cores` ids** are derived from the target, so a rule's undo (same target) releases exactly its cap; "Release all caps" releases every cap Tasktor holds.
- **A guard's Undo** reverses it now and keeps it quiet until its condition clears (otherwise it would re-apply at the next evaluation).
- **Rule badges** (`badge.set`) are kept per rule on the runner for the tray (U4 G3 later); the snapshot contract has no badge field.
- **A destructive action with nothing to do needs no confirm** (the handler returns an immediate result and no work), e.g. "hooks are already set up".
- **I1 busy estimate:** one CPU-time read per agent process every 15 s while agents run (none otherwise); busy = ≥ 0.2 CPU-s in a sample or a new child at a names scan, within 30 s. Reported (hook) sessions attach to their process by pid, else to the only running process of that agent; ended sessions go after 1 min, sessions whose process exited go at once, pid-less ones after 12 h, and their files are deleted.
- **I1's permission toast** is the rule `agent-needs-permission` over the `agent.state` event; the 2-minute wait and the window-in-front check happen in `AgentWatch` (like B2.5), so the rule can still be turned off or reworded.
- **Q1 hooks** target Claude Code's `%USERPROFILE%\.claude\settings.json` (UserPromptSubmit → working, Notification `permission_prompt` → needs-permission, `idle_prompt` and Stop → waiting, SessionEnd → ended). Codex's payload is unverified (OQ-S4), so only Claude Code gets the one-click setup.
- **I12 folders come from the rules:** every enabled `file.created` rule's `folder` (Known Folders resolved) is watched, at most 8; there is no separate folder list.
- **I14 connectivity** uses `NotifyNetworkConnectivityHintChange` (the hint Network List Manager reports) instead of NLM's COM events, and Wi-Fi signal from the connected interface's RSSI (`wlan_intf_opcode_rssi`), read only under a lease; the SSID is never read. The captive-portal sign-in opens Windows' own trigger page in the browser.
- **I7 cache CLIs** are asked only when neither the env var nor the default path exists, and only for pip, npm and uv (the others have no "print the cache dir" command); on Windows they run through `cmd /c` because they are shims.
- **E11:** a block that ends waits for Next (toast or card); +5 min reopens it. A paused focus block is not event-mode time. Stopping after a block ended records it as completed. Measures (C) arrive in M11; until then blocks store no numbers and the card asks to turn on tracking.
- **E8 / E10** ship now (catalog says "later"), as the Module card marked limited and as the off-by-default `tasktor.repos` plugin.
- **I6 and I11** need C's sources (`WinEventSource`, C9 time per workflow), built in M11; they land there.
- **Modules are read at start.** A Module turned on in Settings takes effect after the agent restarts (U4's Settings page restarts it); Core features are always on.

- **SQLite through the C API, no package.** `SqliteDb` binds `sqlite3_*` with `LibraryImport` and a resolver (`winsqlite3.dll` on Windows per D-C9, the system libsqlite3 on Linux), so the agent stays Native AOT safe with no third-party dependency.
- **Episode semantics fixed for parity:** a visit to another app under 30 s is absorbed into the open activity's active time (≥ 2 s counts as a glance), so activities sum to active foreground time; promotion, idle-split and cap boundaries use event timestamps, never check times; activity ids are `run base + builder index` so windows and sessions can refer to open activities; media idle counts as active.
- **Token weights are integer ms**, dwell while the title was shown (distinct tokens per title); TF = log1p(seconds) in both languages.
- **Dense columns** (extract and online): local hour, weekend, active minutes, idle ratio, glances, title changes per minute, job share. Blocks: time [sin, cos, weekend, log1p(min)/log1p(60)], shape [idle, glances/20, rate/5, job], each L2 then weighted.
- **`pca.f32`** is (dims × 17): column 0 is the mean, columns 1–16 the components; signs fixed so the largest loading is positive.
- **Radius** is the 95th percentile of member-to-nearest-exemplar distance with leave-one-out for exemplars (otherwise clusters of ≤ 20 members get radius 0).
- **Assignment picks the highest confidence** (smallest d / r_c) across clusters; ties by id.
- **HDBSCAN is scikit-learn's** (the standalone `hdbscan` package is not in the requirements); DBCV is implemented in the worker (`gates.dbcv`, log-space core distances).
- **G7** reports the 32-dim refit only; the halved / doubled episode-threshold variants need raw events and are not computed from the extract.
- **G4** fits on odd days and assigns even days with the same exemplar assigner; G6b uses the LSA text block.
- **Fixtures are byte-exact** (`.gitattributes` `-text`): `prereg.json`'s hash is stamped into models, so an EOL conversion on Windows would refuse every model.
- **CI** runs on pull requests and pushes to `main` only, with cancel-in-progress, so a branch push gives one run, not two.
- **I6 / I11 (from the parallel lane):** project totals are in memory and re-fed by C9 after a restart; an empty project unmaps; weeks start Monday (local). Window watches are case-insensitive exe + title globs, count as missing only after first seen, fire once after 30 s absent and re-arm; fields carry only the app base name and the user's own pattern.

- **Parallel lanes.** M11 part 2, M12, M13, M14 and M15 were built in separate worktrees with fixed file ownership and merged one by one; the full gate (`scripts/check.sh`) was green after every merge.

- **Capture control is a second pipe** (`PipeName.ForCapture() + "-ctl"`, one command line → one status line per connection) so the browser contract (`tasktor.browser/1`) stays closed to the extension's messages.
- **Tab blocks are keyed by browser + tab id** (`chrome:7`); the agent's tab pause names a tab id (resolved to the browser that reported it) or none (the active visible tab). Timed tab pauses expire like pauses.
- **A browser whose exe is excluded** reports `paused: true` to its extension, so it sends nothing at all.
- **Queued browser context** is drained at start and recorded with `queued: true` (blocks still apply at write time); queued lines carry no browser, so they are recorded as `chrome`; block requests are never queued (the extension gets `capture_not_running`).
- **Capture consent** is `consents.json → modules.capture` (D-C22). Nothing grants it yet: the consent screen is the flyout's (M14 UI), so until then the Module shows "Capture needs your consent first" and no process starts. The agent and the host both check it.
- **Capture exit codes:** 0 = deliberate (another instance, clean stop; not restarted), 3 = no consent (not restarted, "no consent on record"), anything else = crash (D-H9 restart budget). The user's reset after the budget is spent is turning the Module off and on; no new action id was added for it.
- **M14 presets:** maximized slots (and maximized undo targets) are refused with a reason: `SW_SHOWMAXIMIZED` activates and D-W2 gives activation to the shell; the `focus` slot is not activated yet (both belong to `tasktor-shell`). Arrange never changes FancyZones layouts (undo could not restore them); Apply may. A launched slot is reported as launched in the first result; its later move or drop is not sent as an updated result. Concurrent subjects of one rule share an undo key. A drag already in progress when a restore starts is not seen (its move-size start came before the lease).
- **Lifecycle lease scope:** presets lease only while waiting for launched windows (≤ 20 s); a synchronous arrange needs none. The switcher (F) will hold the same lease while the Windows Module is on (U3), on the same thread.
- **T1 classes live in `Tasktor.Capture/Deep`**, not `Tasktor.Core` as C's assembly table lists: they run only in the capture host, and keeping them out of Core keeps the agent free of hook-side code (D-C8 "hooks in tasktor-capture only"). They still use only Contracts / Core shapes.
- **xxHash64 is in-repo** (`Deep/XxHash64.cs`, checked against the reference vectors) rather than the `System.IO.Hashing` package: the source projects carry no runtime package dependency.
- **`RefMinter` sibling index** counts earlier siblings with the same identity (AutomationId, else role + name), so an unrelated insert does not renumber the rest of a list.
- **Re-baseline "every 50 diffs"**: at most 50 diffs chain off one baseline; the 51st record is a baseline.
- **Churn filter:** a ref's changes are emitted until it turns volatile (the 10th text change within 60 s); after that they are withheld and its last value is emitted by `CloseActivity` (as remove + add of that ref). Volatility resets per activity.
- **Side tracks are keyed by app.** Two activities in one app (a YouTube tab behind a chess tab of the same browser) stay on track 1 until the extension's tab media (`Ext.Media`) refines it. A window brought to the front ends its side track at that moment; otherwise a track ends at its last qualifying moment (reported 30 s later).
- **Activity document sections:** `typed`, `first seen view <hwnd>`, `new in view <hwnd>`, `clicked`, `media`; a suppressed run is written as `[password, 12 keys]`; a non-human actor is appended as `(agent:<exe>)`; media lines only on change.
- **Bundled Python verification is by Sigstore, not a pinned hash:** the session cannot reach python.org to compute one, and Sigstore ties the zip to the release manager's identity. If the identity or the bundle URL is wrong, the release fails (fail-closed), never ships unverified.
- **Surfaces direction (U4 amended 2026-11-06):** the maintainer chose edge (at rest) → shelf (sentence over a timeline strip) → command line, with the nine pages moved to a deep window; neutral surfaces + the Windows accent; no cards. Mockups were worked out on a private design canvas; the decisions are in U4's "Amended 2026-11-06" table.
- **Shelf and theme code lives in `Tasktor.Hosts.Common`,** not Core: the viewers reference only Hosts.Common (D-G1), and the sentence is presentation, like `CardFitter`.
- **One palette for every surface.** Surfaces take the mockups' shared stylesheet (Windows Settings values); inks take the later glance boards, which raised contrast at the maintainer's request (dark ink-2 #D6D6D6 / ink-3 #ABABAB, light #111111 / #3D3D3D / #5A5A5A). The light shelf is #F3F3F3, not the stylesheet's #EDEDED: caution text on #EDEDED is 4.49:1, below the 4.5 gate.
- **Type is Segoe UI Variable, not Geologica / Atkinson** (D-G14 updated to match the approved boards): nothing to bundle or license, and it is the Windows system face.
- **Shelf nouns** match exactly (ordinal) in the verdict; a noun not found is skipped and its action stays on the card. Cards whose verdict binding is missing stay silent rather than saying "—".
- **The edge lives with the tray icon in the agent, not in the WinUI process.** D-G10 says the shelf host draws it, but D-H10's row for the process it replaces is "0 MB 30 s after it hides" and U1 D-H9 puts the tray icon in the agent; a resident WinUI process would cost tens of MB at rest. The agent's tray thread will own a GDI layered strip (no WinUI) and launch / signal the flyout on hover or click. Hover needs the strip to take mouse input, so it is not click-through for the cursor; it covers only the taskbar's top 6 px.
- **The flyout process hosts the shelf, the command line and the deep window** (client name `flyout`, origins `flyout` / `shelf` / `command` / `toast`). The project keeps its name to avoid churn.
- **Grain brightness: per-minute worst severity.** `SystemTotals.ObserveSeverity` is fed after every snapshot publish (the only moments a card's severity can change, so a spell shorter than the idle 60 s sample is still seen); each tick stores the minute's worst beside the load points and carries the current severity into quiet minutes. The `series` pull returns it as `severity` (0 / 1 / 2), right-aligned with `hour`; warn or worse is bright.
- **Shelf confirm copy:** the agent's `Summary` is the sentence; the buttons are "Keep it" (accent, focused) and the action's own label.
- **Tray menu scope:** "Pause tracking" is a toggle (the action takes no duration); Focus ▸, Window presets ▸ and Settings are left out until their actions exist on the tray surface. The shelf-open accent on the icon is not drawn: the agent does not know when the flyout is showing.
- **Recording outranks severity on the icon** (the ring must always show while capture records); severity still shows on the shelf and in the menu's sentence.
- **Tests must pass as a standard Windows user.** CI's runner is an administrator, so a test that creates a symbolic link passed there but failed on a normal account (error 1314). The folder-scan loop test now falls back to an NTFS junction (A5 acceptance 4 names a junction loop), and still asserts the link is a reparse point that the scanner does not follow.
- **Command line without the dimmed desktop (for now).** WinUI 3 has no simple transparent full-monitor window; the panel stands alone on the shelf colour. A dim layer would be a separate layered Win32 window under it.
- **The strip's forecast is a display trend, not an agent prediction:** a least-squares line over the lead row's last ten minutes, only labelled when it reaches 100 % within the 15 minutes shown. Events are the hour's alerts; user actions wait for an action history.
- **Browser exe as the app** for app blocks: `chrome.exe` / `msedge.exe`, so "Don't capture this app" on a browser stops its context records too.
